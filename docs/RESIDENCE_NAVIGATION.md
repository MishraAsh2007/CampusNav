Checked November 14, 2026. This work extends Roles 1 and 3.

The current pilot selection is [Brett same-floor wayfinding](RESIDENCE_PILOT_SELECTION.md).
Brown is retained as a private tracing exercise; the source records do not establish
complete verified accessible navigation in any residence yet.

Latest findings: [Indoor data needed](INDOOR_DATA_NEEDED.md) records working SharePoint
access, exhaustive pilot route checks, and the remaining evidence gaps. Brown's builder
now defaults to `brown-house-corrected.json`, which removes the unsupported projected

## What is implemented

The authenticated residence-plan snapshot contains 218 PDFs in 56 building folders.
Several folders are aliases, such as Wheeler and Wheeler Hall. The new batch preparation
groups these into **51 distinct buildings**, with **217 distinct plans within those
buildings** and **349 explicitly identified floor references**. These counts describe
the downloaded source coverage, not a verified inventory of every campus residence floor.
Missing floors are not filled in from neighboring drawings.

Run from the project folder:

```powershell
.\.venv\Scripts\python.exe -m scripts.prepare_all_residences
```

The private output is `data/private/residence_floorplans/workspaces/`. Its `index.json`
lists every building, alias, floor count, plan count and unresolved source issues. Each
building has:

| File | Purpose |
| --- | --- |
| `evidence.json` | Source URLs, hashes, observation/modified times, source floors, all-page label positions and existing traces |
| `plans/<source-id>/page-N.png` | Rendered page for tracing |
| `map.json` | Editable IndoorMap draft with floors and sources; no automatically invented paths |
| `review.json` | Checks for floor mapping, suites/doors, corridors, distances, resident access, elevators and portals |

PDF positions use points, while PNGs are rendered at 1.5 times those coordinates. The
evidence stores that transformation. Word-level extraction keeps separate labels in
the same text block at separate positions; it also records page number and bounds.
Labels in legends, title blocks or dimension text still require exclusion by the reviewer.
No room number is automatically expanded into a floor-specific destination.

Preparation checks source hashes, processes every page, merges identical PDFs within
duplicate building folders, and flags grouped floor templates and missing floor labels.
Existing editable `map.json` and `review.json` files are preserved on reruns. The
generated evidence and rendered images refresh. The input manifest is not modified.

The files remain under the ignored private directory because they came from authenticated
SharePoint. This preparation does not publish the drawings through the public API.

## Brown House

The new [first suite-to-exit pilot](BROWN_FIRST_ROUTE.md) traces a connected first-floor
path with explicit suite and lobby doorways. Its private map, dimension evidence and
visual overlay are generated by `scripts.trace_brown_pilot`. It remains an unverified
draft; no elevator ride or geographic portal is inferred.

An inspected candidate upper-floor main-corridor trace is now stored privately in
`workspaces/brown-house/annotations/brown-upper-main-corridor-east.json`. Its coordinates
use the 1.5x rendered drawing. It stops before uncertain suite/stair/elevator-lobby
connections. Distance and access remain unknown, and it is not a routing edge.
`python -m scripts.annotate_brown` creates the annotation only if it does not already exist.

`campus_notices/trace_annotations.py` provides a separate typed format for this intermediate
work: it accepts unknown metric lengths, requires evidence for any supplied length, and
rejects a reviewed annotation while length or access remains unknown. This avoids filling
the routing schema's mandatory distances with invented values during tracing.

The existing files under `data/private/residence_floorplans/traces/` are preserved:
`brown-house.json` and `brown-house-connected.json`. The new Brown evidence links to both.
They contain nine-floor candidate geometry and the latter has an outdoor portal and
candidate elevator stops. Both remain `draft`; production routing correctly rejects them.

Inspection of the first-floor plan shows suite arrangements: a bedroom label does not
establish a direct doorway to the main corridor. The current Brown generator projects
room-label positions onto a common corridor and uses `0.0254` as a coordinate-to-meter
factor. That factor has no documented drawing-scale basis. The drawing is marked
"Not To Scale" and includes dimension annotations that could support a reviewed local
calibration, but that calibration has not been performed. Candidate grade/access flags
and elevator stops also require review before these traces can be published.

Continue Brown by tracing suite entry doors and internal connections individually,
calibrating distances against documented dimensions, identifying the actual elevator
stops, and checking the plan-to-outdoor entrance alignment. Keep unknown access/grade
values unknown. The new workspace gives the drawing and a review checklist for that work;
it does not copy Brown's projected-room approach into the other residences.

## Routing support for every imported building

The guided resolver and arrival flow previously hard-coded only library/ILC. They now
discover additional building maps from the configured indoor-map directory and use each
map's name/ID for resolution. Once a residence has reviewed topology imported through
`scripts.import_indoor`, the existing `/navigation/catalog`, `/navigation/resolve`,
`/navigation/plan` and `/navigation/arrive` flow can handle it. No separate dorm routing
algorithm or frontend change is required for this backend capability.

Do not copy private workspace drafts into `data/indoor/` merely to expose drawings.
First complete the review and the existing import validation. A residence's resident-only
or keycard-controlled paths also require a suitable access model; the current public-access
Boolean is not an authentication/authorization system.

## Validation and limits

**200 Python tests passed**, including the new all-page extraction, duplicate-folder merge,
checksum failure, preservation of human edits, imported-dorm arrival flow, and rejection
of draft dorm routes. Ruff passed on the changed implementation.

Direct checks of the current real data successfully routed to sampled room destinations
in both ILC and the library, including floor transitions. Both Brown drafts validated as
map documents and were rejected by the production routing gate as expected.

This confirms those tested behaviors; it does not establish that every indoor instruction
matches the physical building. The existing ILC/library maps still contain pilot approaches
whose verification limits are documented in INDOOR_MAPPING.md. All 51 residence workspaces
still require topology review before real dorm navigation is enabled. The existing tests
and source acquisition do not justify claiming bug-free or fully verified campus navigation.
